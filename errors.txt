The NUSTcord application was successfully compiled, and no syntax or compilation errors were found. However, during a manual review of the recently pulled codebase, the following bugs and potential issues were identified:

1. NullPointerException Risk in Session Handling:
   - In `ServerServlet.java` and `MessageServlet.java`, the user ID is retrieved as follows:
     `HttpSession session = req.getSession(false);`
     `int userId = (int) session.getAttribute("userId");`
   - If the user is unauthenticated or the session has expired, `session` could be null, leading to a NullPointerException. Additionally, if the `userId` attribute is missing, auto-unboxing from Object to int will throw a NullPointerException.

2. NumberFormatException Risk in Parameter Parsing:
   - In `ChannelServlet.java`: `int serverId = Integer.parseInt(req.getParameter("serverId"));`
   - In `MessageServlet.java`: `int channelId = Integer.parseInt(req.getParameter("channelId"));`
   - These parameters are parsed without checking if they are null or valid integers. If the parameter is missing or improperly formatted, a `NumberFormatException` will be thrown, causing the request to fail with a 500 Internal Server Error.

3. Resource Leaks in DAOs:
   - In `ServerDAO.java` and `ChannelDAO.java`, when creating new records:
     `ResultSet rs = stmt.getGeneratedKeys();`
   - The `ResultSet` is instantiated but is not closed within a try-with-resources block or a `finally` block. This can lead to minor resource leaks over time.
